# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Arcade Vault: an online games platform where players compete for the highest score. The project follows a spec-driven workflow (`/spec` and `/spec-impl`, from the skills at https://github.com/Klerith/fernando-skills, installed with `npx skills@latest add Klerith/fernando-skills`). The README is written in Spanish. The codebase is still the bare `create-next-app` scaffold (`app/layout.tsx`, `app/page.tsx`, `app/globals.css`).

No test runner is configured yet.

## Next.js version warning

This uses Next.js 16.4.5 with React 19.3, and its APIs differ from older versions. Per `AGENTS.md`, read the relevant guide in `node_modules/next/dist/docs/` (`01-app`, `02-pages`, `03-architecture`, `04-community`) before writing Next.js code, and heed deprecation notices.

## Architecture notes

- App Router only (`app/`). The root layout uses the global `LayoutProps<"/">` type instead of an explicit props interface.
- `next.config.ts` turns on `cacheComponents`, `partialPrefetching` and `experimental.agentFeedback`. `cacheComponents` changes the caching and rendering model, so check the docs before using data fetching or dynamic APIs.
- Tailwind v4 is wired through Turbopack: a `*.css` rule using `@tailwindcss/turbopack` in `next.config.ts`. Theme tokens live in `app/globals.css` under `@theme inline`, with light and dark values set through `prefers-color-scheme`.
- Contact form (`/acerca-de`): the Server Action `app/actions/contact.ts` (`sendContact`) validates on the server (required fields, email format, max lengths, `website` honeypot) and sends a plain-text email with the `resend` SDK. The client form is `app/components/about/contact-form.tsx` (`useActionState`). Errors shown to the user are generic Spanish messages; the real cause is only logged on the server.
- Environment variables (set in `.env.local`, documented in `.env.example`; never commit real values): `RESEND_API_KEY` (required), `CONTACT_TO_EMAIL` (required) and `CONTACT_FROM_EMAIL` (optional, defaults to `Arcade Vault <onboarding@resend.dev>`). With Resend's test sender (`onboarding@resend.dev`), mail is only delivered to the Resend account's own address, so `CONTACT_TO_EMAIL` must be that address until a sending domain is verified. Only read these in server code (`"use server"`), never in Client Components.
- Supabase (foundation, spec 04): two clients in `app/lib/supabase/`. `server.ts` exports `async createClient()` (`createServerClient` + `next/headers` cookies) for Server Components, Server Actions and Route Handlers; with `cacheComponents`, `cookies()` is a request-time API, so call it inside `<Suspense>` or a dynamic context. `client.ts` exports `createClient()` (`createBrowserClient`) for Client Components only. Both throw an error naming the missing variable (never its value). Variables: `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (both required, public by design); `SUPABASE_DB_PASSWORD` is only used by the Supabase CLI, the app never reads it. Use only the publishable key: never `service_role` or the secret key, with or without the `NEXT_PUBLIC_` prefix. There is no `proxy.ts` and no Supabase Auth yet: the session (`av_user`) is still simulated in `localStorage`. Tables, RLS and data access arrived with spec 06 (next bullets). In server code never trust `auth.getSession()`; use `auth.getClaims()`.
- Real games (spec 05 `asteroids`, spec 07 `tetris`, spec 09 `arkanoid`): the engine lives in `app/games/<id>/` as plain TypeScript with no React, no `document` and no globals (`constants.ts`, `input.ts`, `entities.ts`, `ship.ts`, `engine.ts`). `engine.ts` exports `createXxx(canvas, callbacks)` returning `{ pause, resume, destroy }`; callbacks (`onScore`, `onLives`, `onLevel`, `onGameOver`) fire only when the value changes. `destroy` cancels the `requestAnimationFrame` and detaches the `window` listeners, and `resume` resets the timestamp to avoid a `dt` jump. New games should copy this shape. The React wrapper (`app/components/asteroids-canvas.tsx`, Client Component) takes `runId` (changing it destroys the engine and creates a fresh game; this is how "JUGAR DE NUEVO" restarts) and `paused` (`true` while paused or while the end modal is open), and keeps the callbacks in a `ref` so the engine is not recreated on every render. The canvas is a fixed 800×600 scaled by CSS (4:3, no `devicePixelRatio`).
- Tetris (spec 07, catalog id `tetris`, visible title APILADOR, cover `cover-tetris`): engine in `app/games/tetris/` (`constants.ts`, `input.ts`, `pieces.ts`, `board.ts`, `render.ts`, `engine.ts`). Unlike Asteroids, `createTetris(board, next, callbacks)` takes two canvases (board 300×600, NEXT 120×120) and has `onLines` instead of `onLives` (no lives). Keys go through a queue: `input.drain()` returns every `keydown` (including system repeats) and the engine applies them in the next `update`; `setActive(false)` (pause, game over) discards them. `dt` is in ms capped at `MAX_DT_MS = 50`. At game over the engine draws a last frame without the piece that collided and stops its loop. The grid colour is the constant `GRID_COLOR`; the engine never reads CSS. `P` does not pause (only the PAUSA button does). `tetris-canvas.tsx` renders the original screen (`.tetris-stage` > `.tetris-group` of 482×602 with board + HTML side panel), keeps score/lines/level in local state fed by the callbacks (reset by `runId`) and scales the whole group with `transform: scale(k)` from a `ResizeObserver` (hidden until the first measure). `.tetris-group` resets font-size, line-height, letter-spacing and colour so the platform styles do not leak into the panel.
- Arkanoid (spec 09, catalog id `arkanoid`, visible title ROMPEBLOQUES, cover `cover-arkanoid`, `magenta`, `ARCADE`, `sort_order` 2): engine in `app/games/arkanoid/` (`constants.ts`, `input.ts`, `levels.ts`, `sprites.ts`, `engine.ts`) with the same shape as Asteroids (one 800×600 canvas, callbacks `onScore`, `onLives`, `onLevel`, `onGameOver`; `hud: { lives: true, level: true }`). Assets live in `public/games/arkanoid/` (`spritesheet-breakout.png`, `ball-bounce.mp3`, `break-sound.mp3`) and load by URL (`/games/arkanoid/...`): the loop starts only when the spritesheet promise resolves, and `destroy` before that prevents it. `dt` is in seconds capped at `MAX_DT = 0.05`. Controls: ← → (`input.ts`, by `code`, cleared on `blur` and on `resume`) and `mousemove` on the canvas converted with `getBoundingClientRect` (CSS scale); both are ignored while paused or finished. Win (level 5 cleared) and defeat (0 lives) both fire `onGameOver` once: the engine draws a last frame with the HUD, detaches the keyboard and stops its loop, and `resume` does not revive it. The 2 sounds play as a clone per event with the `play()` rejection ignored (browser blocks audio before a gesture); there is no mute or volume. No `P`/`Escape` pause and no level selector (it allowed farming points). The canvas HUD says `Puntos:` instead of `Score:`. Max score is 2 080 (208 blocks × 10). The spritesheet and sounds come from the course reference: check their licence before publishing. In dev, Strict Mode mounts two engines, so each MP3 is requested twice.
- Engine registry (spec 07): `app/games/registry.ts` exports `REAL_GAMES: Record<string, { Canvas, hud: { lives, level } }>` and `RealCanvasProps` (`runId`, `paused`, `onScore`, `onLives`, `onLevel`, `onGameOver`; games without lives receive `onLives` and never call it). `GamePlayer` (`app/components/game-player.tsx`) looks the game up there (`Object.hasOwn`) and renders `real.Canvas`, feeding score/lives/level from the callbacks; the bar hides the Vidas box when `hud.lives` is `false` (Tetris shows Jugador, Puntuación, Nivel). There is no simulator any more (spec 08 removed the 8 dummy games, `localStorage["av_scores"]` and their covers): `/juegos/[id]/jugar` calls `notFound()` when the id is not in `games` or not in `REAL_GAMES`, and every score goes through the Server Action `saveScore` (see the spec 06 bullet).
- Data model (spec 06): migration `supabase/migrations/20261119230825_games_and_scores.sql`, applied with the Supabase MCP (`apply_migration`; the file name must match the version in the remote `schema_migrations`). Tables `games` (`id` text slug PK, `title`, `short`, `long`, `cat`, `cover`, `color`, `sort_order` unique; seeded with 9 dummy games that spec 08 deleted) and `scores` (`id` uuid, `game_id` FK, `name` 1-10 chars, `score` int 0..10,000,000, `created_at`; index `(game_id, score desc, created_at asc)`). View `games_with_stats` (`security_invoker = on`) adds `best` = MAX(score) and `plays` = COUNT(*), both 0 when there are no scores. RLS is on for both tables: `select` for `anon` and `authenticated`; `scores` allows `insert` only through the policy `scores_insert_real_games` (`game_id in ('asteroids', 'tetris', 'arkanoid')`, migration `20261122023318_arkanoid.sql`, which recreated it from `20261121232230_tetris.sql`); no `update` or `delete`, and no writes to `games`. Each new real game must add its id to that policy (new migration that drops and recreates it), to `REAL_GAME_IDS` in `app/actions/scores.ts` and to `REAL_GAMES` in `app/games/registry.ts`. Migration `20261121235726_quitar_juegos_simulados.sql` (spec 08) deleted the 8 dummy games: `games` has 3 rows after spec 09, `asteroids` (`sort_order` 0), `tetris` (1) and `arkanoid` (2); the next real game takes `sort_order` 3. With no Auth, anyone can send a fake score through the REST API or the action: this is accepted for now (no `user_id`, rate limiting or anti-cheat yet).
- Data layer: `app/lib/supabase/database.types.ts` is generated (`generate_typescript_types`), never edit it by hand, and regenerate it after every migration; both `createClient` functions are typed with `Database`. View columns come back as `| null`, so `app/lib/games.ts` (`import "server-only"`) maps rows to `Game` and exports `getGames()`, `getGame(id)`, `getLeaderboard(gameId, limit)` (order: score desc, then `created_at` asc; `rank` 1..N computed there), and for the home `getRecentScores(limit)` (latest scores across games with the game title and colour) and `getTopScores(limit)` (best scores across games). They read `cookies()` through the server client, so call them inside `<Suspense>` (as `/`, `/biblioteca`, `/salon` and `/juegos/[id]` do) or from a Server Action, and catch their errors to show a Spanish message. `app/data/games.ts` only keeps the types and `CATEGORY_ORDER` (`/biblioteca` shows the chips TODOS plus only the categories that have at least one game); the `GAMES` constant and the fake `seededScores` are gone. There is no `generateStaticParams` for `/juegos/[id]`: a missing game calls `notFound()`, which renders the 404 page with `noindex` but status 200 because it streams inside `<Suspense>`. Dates are formatted `dd/mm/aaaa` in UTC with `app/lib/format-date.ts`, which also exports `formatAgo(iso)` ("hace 5 min"); it calls `Date.now()`, so use it only in a suspended Server Component after `await connection()` (never in the module scope or in a Client Component).
- Saving a score (spec 06): `saveScore({ gameId, name, score })` in `app/actions/scores.ts` (`"use server"`) validates on the server (`gameId` must be in `REAL_GAME_IDS`, today `asteroids`, `tetris` and `arkanoid`; name trimmed, uppercased, 1-10 chars; score an integer 0..10,000,000) and inserts with the publishable key. Errors shown to the user are generic Spanish text; the real cause is only logged. `GamePlayer` calls it for every game (they are all in the registry), disables the button while saving (a `ref` also blocks double clicks) and lets the player retry on failure. Leaderboards: top 10 in `/juegos/[id]` (`app/components/leaderboard.tsx`) and top 12 per game in `/salon` (`hall-board.tsx`, podium and table handle fewer than 3 and fewer than 12 rows, with an empty state). The home (spec 08) reads real data in `app/components/home/live-data.tsx` (async Server Components inside `<Suspense>`, each with loading, empty and error states): the stats JUEGOS and PARTIDAS come from `getGames()`, "ÚLTIMAS PUNTUACIONES" from `getRecentScores(7)` and "TOP JUGADORES" from `getTopScores(5)`; `app/data/home.ts` only keeps fixed text.
- Path alias: `@/*` maps to the project root.
- Fonts: Geist and Geist Mono are loaded in `app/layout.tsx` as the CSS variables `--font-geist-sans` and `--font-geist-mono`.
