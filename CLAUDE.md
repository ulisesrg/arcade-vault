# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Arcade Vault: an online games platform where players compete for the highest score. The project follows a spec-driven workflow (`/spec` and `/spec-impl`, from the skills at https://github.com/Klerith/fernando-skills, installed with `npx skills@latest add Klerith/fernando-skills`). The README is written in Spanish. The codebase is still the bare `create-next-app` scaffold (`app/layout.tsx`, `app/page.tsx`, `app/globals.css`).

No test runner is configured yet.

## Next.js version warning

This uses Next.js 16.4.5 with React 19.3, and its APIs differ from older versions. Per `AGENTS.md`, read the relevant guide in `node_modules/next/dist/docs/` (`01-app`, `02-pages`, `03-architecture`, `04-community`) before writing Next.js code, and heed deprecation notices.

## Architecture notes

- App Router only (`app/`). The root layout uses the global `LayoutProps<"/">` type instead of an explicit props interface.
- `next.config.ts` turns on `cacheComponents`, `partialPrefetching` and `experimental.agentFeedback`. `cacheComponents` changes the caching and rendering model, so check the docs before using data fetching or dynamic APIs.
- Tailwind v4 is wired through Turbopack: a `*.css` rule using `@tailwindcss/turbopack` in `next.config.ts`. Theme tokens live in `app/globals.css` under `@theme inline`, with light and dark values set through `prefers-color-scheme`.
- Contact form (`/acerca-de`): the Server Action `app/actions/contact.ts` (`sendContact`) validates on the server (required fields, email format, max lengths, `website` honeypot) and sends a plain-text email with the `resend` SDK. The client form is `app/components/about/contact-form.tsx` (`useActionState`). Errors shown to the user are generic Spanish messages; the real cause is only logged on the server.
- Environment variables (set in `.env.local`, documented in `.env.example`; never commit real values): `RESEND_API_KEY` (required), `CONTACT_TO_EMAIL` (required) and `CONTACT_FROM_EMAIL` (optional, defaults to `Arcade Vault <onboarding@resend.dev>`). With Resend's test sender (`onboarding@resend.dev`), mail is only delivered to the Resend account's own address, so `CONTACT_TO_EMAIL` must be that address until a sending domain is verified. Only read these in server code (`"use server"`), never in Client Components.
- Supabase (foundation, spec 04): two clients in `app/lib/supabase/`. `server.ts` exports `async createClient()` (`createServerClient` + `next/headers` cookies) for Server Components, Server Actions and Route Handlers; with `cacheComponents`, `cookies()` is a request-time API, so call it inside `<Suspense>` or a dynamic context. `client.ts` exports `createClient()` (`createBrowserClient`) for Client Components only. Both throw an error naming the missing variable (never its value). Variables: `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (both required, public by design); `SUPABASE_DB_PASSWORD` is only used by the Supabase CLI, the app never reads it. Use only the publishable key: never `service_role` or the secret key, with or without the `NEXT_PUBLIC_` prefix. There is no `proxy.ts` and no Supabase Auth yet: the session (`av_user`) is still simulated in `localStorage`. Tables, RLS and data access arrived with spec 06 (next bullets). In server code never trust `auth.getSession()`; use `auth.getClaims()`.
- Real games (spec 05, only `asteroids` so far): the engine lives in `app/games/<id>/` as plain TypeScript with no React, no `document` and no globals (`constants.ts`, `input.ts`, `entities.ts`, `ship.ts`, `engine.ts`). `engine.ts` exports `createXxx(canvas, callbacks)` returning `{ pause, resume, destroy }`; callbacks (`onScore`, `onLives`, `onLevel`, `onGameOver`) fire only when the value changes. `destroy` cancels the `requestAnimationFrame` and detaches the `window` listeners, and `resume` resets the timestamp to avoid a `dt` jump. The next games (`03-tetris`, `04-arkanoid`) should copy this shape. The React wrapper (`app/components/asteroids-canvas.tsx`, Client Component) takes `runId` (changing it destroys the engine and creates a fresh game; this is how "JUGAR DE NUEVO" restarts) and `paused` (`true` while paused or while the end modal is open), and keeps the callbacks in a `ref` so the engine is not recreated on every render. The canvas is a fixed 800×600 scaled by CSS (4:3, no `devicePixelRatio`).
- `GamePlayer` (`app/components/game-player.tsx`) branches on `game.id === "asteroids"` (`isReal`): it renders `AsteroidsCanvas` and feeds score/lives/level from the engine callbacks. The other 8 games keep the simulator (random score interval, decorative arena). Refactor into an engine registry only when a second real game arrives. Saving the score differs: Asteroids calls the Server Action `saveScore` (see the spec 06 bullet) and the other 8 simulators still write `localStorage["av_scores"]` with `game: game.id`, so their random scores never reach the database. The catalog entry `rocas` is a known duplicate of `asteroids`, left untouched on purpose.
- Data model (spec 06): migration `supabase/migrations/20261119230825_games_and_scores.sql`, applied with the Supabase MCP (`apply_migration`; the file name must match the version in the remote `schema_migrations`). Tables `games` (`id` text slug PK, `title`, `short`, `long`, `cat`, `cover`, `color`, `sort_order` unique; 9 rows seeded from the old `GAMES`) and `scores` (`id` uuid, `game_id` FK, `name` 1-10 chars, `score` int 0..10,000,000, `created_at`; index `(game_id, score desc, created_at asc)`). View `games_with_stats` (`security_invoker = on`) adds `best` = MAX(score) and `plays` = COUNT(*), both 0 when there are no scores. RLS is on for both tables: `select` for `anon` and `authenticated`; `scores` allows `insert` only with `game_id = 'asteroids'`; no `update` or `delete`, and no writes to `games`. Each new real game must add its id to that policy (new migration) and to `REAL_GAME_IDS` in `app/actions/scores.ts`. With no Auth, anyone can send a fake score through the REST API or the action: this is accepted for now (no `user_id`, rate limiting or anti-cheat yet).
- Data layer: `app/lib/supabase/database.types.ts` is generated (`generate_typescript_types`), never edit it by hand, and regenerate it after every migration; both `createClient` functions are typed with `Database`. View columns come back as `| null`, so `app/lib/games.ts` (`import "server-only"`) maps rows to `Game` and exports `getGames()`, `getGame(id)` and `getLeaderboard(gameId, limit)` (order: score desc, then `created_at` asc; `rank` 1..N computed there). They read `cookies()` through the server client, so call them inside `<Suspense>` (as `/`, `/biblioteca`, `/salon` and `/juegos/[id]` do) or from a Server Action, and catch their errors to show a Spanish message. `app/data/games.ts` only keeps the types and `CATEGORIES`; the `GAMES` constant and the fake `seededScores` are gone. There is no `generateStaticParams` for `/juegos/[id]`: a missing game calls `notFound()`, which renders the 404 page with `noindex` but status 200 because it streams inside `<Suspense>`. Dates are formatted `dd/mm/aaaa` in UTC with `app/lib/format-date.ts`.
- Saving a score (spec 06): `saveScore({ gameId, name, score })` in `app/actions/scores.ts` (`"use server"`) validates on the server (`gameId` must be `asteroids`; name trimmed, uppercased, 1-10 chars; score an integer 0..10,000,000) and inserts with the publishable key. Errors shown to the user are generic Spanish text; the real cause is only logged. `GamePlayer` calls it only for `asteroids`, disables the button while saving (a `ref` also blocks double clicks) and lets the player retry on failure. Leaderboards: top 10 in `/juegos/[id]` (`app/components/leaderboard.tsx`) and top 12 per game in `/salon` (`hall-board.tsx`, podium and table handle fewer than 3 and fewer than 12 rows, with an empty state). `RECENT_SCORES` and `TOP_PLAYERS` on the home are still fictional.
- Path alias: `@/*` maps to the project root.
- Fonts: Geist and Geist Mono are loaded in `app/layout.tsx` as the CSS variables `--font-geist-sans` and `--font-geist-mono`.
